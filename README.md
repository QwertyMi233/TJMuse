# TJMuse

**把今天理清，把时间留给想做的事。**

TJMuse 是一款面向 iOS 和 Android 的日程管理应用，将待办清单、循环任务、中国大陆节假日与调休信息、AI 时间规划放在一起。它从学生的学习与日常生活出发，让有明确时间的任务和可以自由安排的事项各有位置。

当前版本为 **0.1.0**。Android APK 和 iOS 未签名 IPA 已完成构建与文件校验；安装后的运行表现仍需真机验证。产品文案见 [项目介绍](项目介绍.md)，具体检查结果见 [VERIFICATION.md](VERIFICATION.md)。

## 功能与版本范围

底部导航包含 **To-do、AI、作业、我的** 四个页面。

| 模块 | 0.1.0 已实现内容 |
| --- | --- |
| To-do | 周历、月内周次、日期跳转、返回今天；按时间展示任务，支持勾选完成、编辑、删除、描述、地点、预计时长与卡片颜色 |
| 任务编辑 | 一次性任务及子任务；每 N 天／周／月／年循环，按周循环可选择多个星期 |
| AI | 根据当天任务、自由事项、调休信息与作息，请求生成具体到分钟的自然语言规划；支持追问、重新生成、取消和失败重试 |
| 自由事项 | 独立于日程清单保存没有固定时间的事项，支持名称、描述、编辑与完成状态 |
| 主页摘要 | 在 To-do 页面查看当天最新的 AI 规划摘要 |
| 中国大陆调休 | 内置 2026 年放假调休数据，支持按年联网同步与本地缓存 |
| 我的 | 编辑头像、昵称、国家／地区与性别；设置主题颜色、AI 接口、提醒、每周第一天和可安排时间；清除历史对话 |
| 本地保存 | 保存任务、每次循环的完成状态、自由事项、资料、设置和最近最多 500 条对话 |

**后续计划：**Canvas 信息读取与分析、课表录入与解析、作业手动／自动导入。当前“作业”页仅保留标题，“关于我们”内容留空；课程数据类型与课程提醒开关已预留，尚未提供课表录入入口。

## 安装现有构建

本机 `releases/` 目录中已有以下产物。该目录不纳入版本库，复制源码或下载仓库不一定包含安装包。

| 平台 | 文件 | 安装要求 |
| --- | --- | --- |
| Android | `TJMuse-0.1.0-arm64-v8a.apk` | ARM64 设备，Android 7.0／API 24 及以上；已使用本地发行证书签名 |
| iOS | `TJMuse-0.1.0-unsigned.ipa` | iPhoneOS ARM64，iOS 16.4 及以上；需使用自己的签名工具签名后安装 |

每个安装包附带 `.sha256` 校验文件。构建与验证信息保存在 `releases/build-info.json`。当前 Android 产物为 APK 格式。

## 开发环境与启动

使用 **Node.js 24 LTS** 和 **pnpm 11.25.0**，在项目根目录执行：

```sh
pnpm install
pnpm web
```

这会启动浏览器开发预览。移动端预览可运行：

```sh
pnpm start
```

使用支持本项目 Expo SDK 的 Expo Go 扫码。验证系统通知、原生导航与选取器时，建议安装原生开发构建或 Release 安装包。

当前 Windows 工作区也可通过 PowerShell 启动：

```powershell
./scripts/dev.ps1 -Platform web
```

该脚本支持 `web`、`mobile`、`android` 和 `ios`，并能识别当前电脑已有的 Codex Node 运行时。Android 本机编译需要 JDK 和 Android SDK；iOS 本机编译需要 macOS 与 Xcode，Windows 可使用 EAS 云构建。

## 第一次使用

1. 在 **To-do** 页选择日期，点击右下角加号，添加一次性或循环任务。
2. 在 **AI** 页下方添加没有固定时间的自由事项，例如阅读、运动或整理笔记。
3. 打开 **我的 → AI 设置**，选择服务商，填写 API Key、接口地址和模型 ID。支持 ChatGPT、DeepSeek 与自定义 Chat Completions 兼容接口；模型是否可用取决于服务商和账户权限。
4. 在 **我的** 中设置 AI 可安排的时间范围，再进入 **AI** 页生成当天规划。可以继续发送文字，请 AI 调整安排。
5. 按需开启 To-do 通知，选择准时或提前提醒；在“中国大陆调休”中同步需要的年份。

每次进入 AI 页面会尝试自动发起规划请求，可能产生服务商 API 费用。未配置密钥时会显示设置入口。AI 给出时间建议，当前不会自动创建或修改任务。

## 平台界面

- **iOS：**使用系统原生标签栏，在支持的系统上采用 Liquid Glass 浮动效果；旧系统采用对应的标准标签栏。日期与时间分别通过系统选取器设置。
- **Android：**使用平台原生 Material 标签栏；独立构建配置 Material 3 主题及日期／时间选取器。Expo Go 使用其运行环境支持的选取器。
- **Web：**提供交互预览，使用半透明浮动导航和浏览器日期／时间控件。Web 预览不能用于确认原生玻璃效果或系统提醒送达。

页面遵守系统安全区，顶部为真实系统状态栏留出空间。

## 数据、隐私与使用约定

任务、设置、个人资料和对话保存在设备本地，当前没有账号体系或跨设备云同步。日常记录与勾选任务不依赖 AI 服务。

原生端 API Key 通过 `expo-secure-store` 保存到系统安全存储；Web 端密钥只保留在内存，刷新后需要重新填写。生成规划时，所需任务、自由事项和相关日程上下文会直接发送到用户配置的 HTTPS AI 服务商，不经过 TJMuse 中转服务器。

日期与提醒使用设备本地时区。循环任务按每次日期分别记录完成状态；编辑循环任务会修改整个系列。按月／年循环遇到不存在的日期时取当月最后一天，后续仍保留原始日期作为计算依据。

### 调休与提醒

内置 2026 年中国大陆放假调休安排；联网数据来自 [holiday-cn](https://github.com/NateScarlet/holiday-cn)，通过 jsDelivr 按年获取并缓存。获取失败时保留已有数据，未获取的年份显示未知，不猜测补班日期。个人资料中的地区不会自动切换调休规则，调休显示由单独开关控制。

通知权限仅在用户开启提醒时申请。应用会在任务／设置变化或回到前台时，更新未来 60 天内最近 48 条本地提醒；长期不打开应用时不会持续补充。提醒送达还受系统权限和省电设置影响，Web 端不提供本地定时提醒。

## 技术栈与目录

当前工程使用 Expo SDK 58、React Native 0.88、React 19.3、TypeScript 6 和 Expo Router；状态通过 AsyncStorage 本地持久化，原生密钥独立存储。

```text
app/                     页面路由、全局布局与底部导航
src/
  core/                  数据类型、默认值、日期与循环规则、提醒计算
  screens/               To-do、AI、作业、我的四个主页面
  services/              AI 请求、调休同步、通知与密钥存储
  state/                 应用状态与本地持久化
  ui/                    任务卡片、编辑弹层、设置与共用组件
  assets/                模型标识资源
assets/                  应用图标与平台图标
plugins/                 原生主题配置插件
scripts/                 启动、构建、预览与验证脚本
tests/                   日期、循环、提醒和 AI 请求测试
.eas/build/              iOS 未签名云构建流程
```

## 构建与验证

完整工具链准备、签名、EAS 配置和校验步骤见 **[BUILDING.md](BUILDING.md)**。已准备好本机工具链时，Android Release 可运行：

```powershell
./scripts/build-android.ps1
```

iOS 未签名云构建使用 `ios-unsigned` 配置：

```sh
eas build --platform ios --profile ios-unsigned
```

工程当前已关联 Expo 项目；使用其他账户维护或派生项目时，需重新关联，并检查 `app.json` 中的 `owner`、`extra.eas.projectId` 与应用标识。云构建需要可用的 Expo 登录和账户配额。未签名构建无需 Apple 签名凭据，生成的 IPA 仍需自签后安装。

Windows 原生构建需保留 `pnpm-workspace.yaml` 中的 `nodeLinker: hoisted` 和现有 CMake 路径配置。`.build-tools/signing/` 中的发行证书应单独备份，后续 Android 更新需沿用同一签名；工具缓存、签名文件、环境文件和构建产物均已排除上传。

已有验证包括类型检查、11 项自动化测试、三平台资源导出、浏览器交互回归和两个原生安装包的文件校验。**真实设备启动、通知送达、相册访问和原生视觉效果仍待验证；真实 AI 服务调用尚未使用用户密钥测试。**详情见 [验证记录](VERIFICATION.md)。
